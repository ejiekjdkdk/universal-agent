## 兼容性与剩余限制

1. 撤销策略更严格：撤权后旧模型上下文和有检索依赖的任务读取会拒绝；这是有意的安全行为变化。历史数据库中缺失的来源依赖不会自动补写；本轮保证新记录路径及已有可识别依赖，不保证追溯还原旧任务的数据来源。部署升级应重启进程清空旧内存缓存。
2. 复杂但合法的 Schema 若超出 2 秒实际校验预算或 8 MiB 序列化限额也会拒绝。依赖初始化另有 5 秒等待上限；总调用或取消可等待两阶段剩余时间及回收，不能宣称 2 秒 API 响应 SLA。同步技能校验仍可能等待这段有界时间；没有操作系统级内存/CPU 配额或高负载压力验收。
3. 隔离校验子进程只传本次 JSON 和必要 Windows 环境项，禁止网络引用；这不构成抵御同一系统账号恶意代码的安全沙箱。快速路径只接受小型、有限深度、无正则/引用/组合的基础规则。
4. 日志保护针对锁定 `mcp==2.3.0` 客户端/分发器日志名称；SDK 升级须重新检查。未保证自定义 HTTP 调试器、系统日志或其它应用日志均受此过滤器保护。
5. 恢复测试使用确定性时间推进、SQLite 双连接交错和已有线程并发；没有进程强杀、磁盘故障、时钟回拨或长期压力注入。外部有副作用系统的恰好一次执行仍需业务协议保证；没有真实企业写入验证。
6. 继续限定 Windows/Python 3.11/本机 SQLite。MCP stdio、DNS/企业私网、真实公网生产服务、PostgreSQL、分布式协调和自主多模型协作不属于已验收能力。本地 HMAC 发布不是 PKI/SSO 或独立人员审批。
7. 新完整结果加密不代表整库加密；旧答案、证据和 Mock 账本仍按原设计保存。逻辑删除不保证介质擦除。
