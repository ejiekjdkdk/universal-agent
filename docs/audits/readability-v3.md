## 行为审计与修复

### 超大整数时间戳

原 `_number` 对所有整数调用 `math.isfinite`。合法 JSON 可以携带 `10**400` 或其负值，转换到浮点数时抛出 `OverflowError`，导致已正确签名的事件越过正常的 `Fault` 拒绝审计。

新增用例分别覆盖 `issued_at`、`expires_at` 的正负超大整数。原代码四项均因 `OverflowError` 失败；修复后四项均通过。现在这类输入返回 `422 / TRIGGER_INVALID`，记录 `trigger.ingress / deny`，不创建任务、计划、会话、事件回执或 nonce。

这是本轮唯一有意改变的运行行为：将原未处理异常归入已有的无效输入契约，正常事件和签名算法不变。

### Schema 方言限制

复核发现：Skill 的导入及 Runtime 校验固定使用 Draft 2020-12，根 `$schema` 不会选择其他方言。本地 `$dynamicRef` 生效；旧 `$recursiveRef` 被该校验器忽略，不能依赖它实施约束。

文档原来的“禁止外部引用”不等于禁止所有本地动态引用。本轮撤回这一误判，只在 [SkillOps 文档](../v3/skillops.md) 澄清现有行为，不更改旧发布的加载规则。收紧方言或不支持关键字的门禁属于后续治理改进，须先盘点旧包并提供新版本迁移路径。该限制仍然存在，不能把本次回归通过表述为任意 Schema 的约束均生效。
