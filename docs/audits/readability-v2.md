# V2.0 代码审计与可读性整理

审计基线为 `5f6090c`，范围包括后端、调试与审批网页、场景、独立项目模板、启动脚本和测试。按用户的十条准则检查可读性，并独立对照 V1/V2 设计与发布治理契约。审计分支为 `codex/readability-audit`。

## 提示词的适用范围

以“新人能否沿着一次请求读懂选择、鉴权、执行和持久化”作为判断标准，可以直接实施。第 8 条末尾的“异常处”按“异常处理”理解。对于事务上下文、框架路由装饰器、取消传播、执行前后复查权限，数量和缩进层数不能单独决定是否精简。源码中的中文说明与作为 API 契约、SQL、错误码或命令行输出的字符串分别核对。

## 规格审计 · 修复前的复现记录

首次审计在独立的 `5f6090c` 副本中复现了前三项，通过核对步骤查询与事件构造发现了第四项。可读性提交 `fd22d0a` 保留了这些行为。下表描述当时的触发条件，修复后的行为和回归用例见下一节。

| 优先级 | 触发条件和影响 | 修复方向 |
| --- | --- | --- |
| 高 · 发布门禁可能误放 | 一个已由操作方批准源码摘要的**自定义** Python 工具，声明 `snapshot_files=["extra.txt"]`，并在文件存在时读取它、缺失时走备用逻辑。发布快照包含该文件，评测临时目录未复制它。用备用结果作金标时评测通过，但实际返回附属文件内容。见 [快照打包](../../app/snapshots.py) 的 `_bundle` 与[离线评测](../../app/evaluations.py) 的 `_isolated_catalog`。 | 评测须使用实际快照中经过路径与类型校验的同一组声明文件；无法安全复现时拒绝放行。增加“有文件与无文件行为不同”的门禁用例。 |
| 中 · 旧场景可能阻止服务启动 | 同一份合法 JSON 笔记数据改名为 `notes.txt` 并修改 `documents` 引用。场景目录加载器可读取，启动时快照打包要求扩展名为 `.json`，即使场景只用于即时执行也会报错。见 [Catalog._load](../../app/catalog.py) 和 [Snapshots.__init__](../../app/snapshots.py)。 | 明确未托管旧场景的兼容策略，使加载和发布校验一致，并保留路径/链接检查。现有用户可先将文件名及引用改回 `.json`。 |
| 中 · 即时任务的导出缺少版本归属 | 创建绑定发布快照、没有计划行的 reactive 任务。`Store.task_snapshot` 可读到绑定，但 [OTLP 根 span 查询](../../app/observability.py) 仅从 `plans` 取摘要，导出缺少 `agent.release_id`，会影响按发布追溯故障。 | 从任务绑定读取发布摘要，兼容已有持久计划数据。分别覆盖 reactive、durable 和历史无绑定任务。 |
| 低 · 审批后的尝试次数显示口径不一 | [步骤调度与展示](../../app/plan_store.py) 中，`claim_step` 的执行尝试数扣除了提案阶段占用的令牌，而 `plan_view` 与重试事件基于原始令牌。例如提案后第一次实际提交可在两个视角分别显示为第 1、第 2 次。 | 将物理领取次数和实际执行尝试分别定义，补充事件与展示的一致性用例；租约围栏继续使用独立的单调令牌。 |

## 四项问题的修复与回归

| 原始问题 | 修复后的行为 | 已验证的边界 |
| --- | --- | --- |
| 发布门禁漏掉声明的附属文件 | 门禁从已核验的快照取原始字节，离线命令按同一份文件清单取样。适配器可读取随包发布的附属数据。 | 同一适配器在有文件和缺文件时返回不同答案。正确金标通过，仅匹配缺文件答案的金标被拒绝。评测中途篡改磁盘快照会阻止发布。[回归用例](../../tests/test_snapshot_evaluation.py) |
| 旧场景资料后缀导致启动失败 | 加载和打包都按 UTF-8 JSON 内容与资料结构校验，允许合法的本地资料文件使用中文名和其他后缀。 | 用 `会议笔记.txt` 启动服务并发起即时问答，从快照重新检索得到相同证据。越界路径、隐藏文件、保留文件名和结构错误的内容被拒绝。[回归用例](../../tests/test_legacy_documents.py) |
| 即时任务的 Trace 缺少发布版本 | OTLP 根 span 从任务入库时绑定的快照读取 `agent.release_id`。旧持久计划可从计划记录还原。 | 即时与持久任务按各自绑定导出。历史任务无可核实的绑定时省略该属性，事件中伪造的版本无法覆盖真实绑定。[回归用例](../../tests/test_observability.py) |
| 审批后首次执行显示第 2 次 | 步骤查询、新事件与工作台统一按提案和执行阶段计数，租约令牌单独递增。 | 已批准、尚未领取执行任务时为 0，首次领取为 1。过期重领按阶段递增，仅核验缓存回执的租约不再增加次数。已存历史事件保留原始载荷。[审批回归](../../tests/test_approvals.py) · [恢复回归](../../tests/test_plan_store.py) |

## 首次可读性整理的兼容性影响

- `notes`、`text`、`project_brief` 及独立模板 `project_records` 的适配器只改了模块说明。四份适配器除文档字符串外的 Python 语法树与基线相同。由于快照按字节校验，四个示例清单的包版本从 `1.0.0` 升至 `1.0.1`；新任务可能显示新版本和新的快照 ID，资料记录版本保持原值。
- 三个内置 Python 场景的运维金标显式保留旧摘要。未配置 `previous_adapter_sha256` 时仍仅信任当前摘要；配置后，只有列出的旧源码可以继续接受相同金标评测。已部署的自定义场景须使用其自己的审核记录，不应把本次示例摘要直接复制过去。详见[评测说明](../../evals/README.md)。
- 中文 Docstring 改变 Python 反射获得的说明文本，重新排版会改变源码行号。HTML 缩进产生的纯空白文本节点可能影响自行编写的 `childNodes` 索引；已有元素标识、属性、非空文本及浏览器操作已核对。
