# V3 高风险代码审计

日期：2026-11-03。审计基线：main 的 `18f9272`。修复分支：`codex/v3-safety-audit`。

本轮重点是越权读取、数据泄露、未经当前授权的写入、重复提交、租约与恢复、发布快照和 MCP 边界，不是再次做风格整理。以现有 V3 Windows 本机框架为验收范围，V4/V5 仍是长期愿景。

## 已确认并修复的高优先级问题

### P1：SSE 缓存批次在撤权后仍可能发送回答

原 `app/main.py` 的 `event_stream` 每批读取事件前鉴权一次；循环中的每次 `yield` 都可能等待网络发送。首帧发送后撤销用户的权限，已缓存的同批 `message_delta`、`task_completed` 仍可能继续发出。

复现使用真实路由的 `StreamingResponse.body_iterator`、Runtime 与临时 SQLite：先读取 `task_started`，再撤销权限。直接调用任务授权已经返回 `PERMISSION_DENIED`，继续推进原迭代器却仍得到事件和敏感回答标记。

修复在每条事件 yield 前重新调用既有 `allowed_task`。新增三个用例覆盖权限、对象范围、资源类型撤销；原实现均失败，修复后通过。已建立的流在失去权限后终止，不再产生下一条受保护事件。响应头已经发出时不会改写成新的 HTTP 状态码；已发送的数据也无法撤回。

### P1：触发来源撤销后，已获批的模拟写入仍可能落账

`PlanWorker` 的 `mock_ledger` 路径直接进入审批事务，没有经过普通工具 Gateway 的任务授权。原审批逻辑复查角色、审批人、摘要、对象版本与发布，却漏掉 `TriggerGateway.guard_task` 的来源检查。

复现经过真实 HMAC 事件接入、任务创建、提案及独立审批：随后禁用来源，直接调用来源守卫已经拒绝，Worker 却仍完成任务，模拟账本和回执各新增一条。

修复在 `_mock_requester` 内进入 `Runtime.authorize_task`，并在落账前再次执行任务授权；两处检查均在原 SQLite 写事务中，保留随后执行的租约和审批期限检查。异常先回滚，再由 Worker 按既有机制结算失败。

新增九个拒绝用例覆盖“提案前、批准后、提交过程中”与“来源禁用、范围缩小、来源身份改变”的组合。另有一个正常授权用例确认账本和回执只提交一次。现有产品仅允许本地模拟账本，没有因此发生真实企业系统写入。

## 复核范围与结论边界

| 范围 | 本轮核对 |
| --- | --- |
| 身份与读取 | 租户/组织/用户三字段隔离，任务及会话重开，幂等分区，历史对象和资源类型传播，Trace 与 SSE，普通用户/服务/管理凭据分离。SSE 的确认问题已修复。 |
| 执行与恢复 | 执行前后授权、物理调用预算、独立委派并发槽、取消传播、租约 token、过期领取、审批人资格、摘要和对象版本、账本/回执/结算事务。触发模拟写路径的确认问题已修复。 |
| 发布与技能 | 快照路径和摘要、冻结内容、签名、发布门禁、计划输入引用与工具绑定。未发现本轮可复现的同等级新问题。 |
| MCP | 固定字面 IP、无重定向、独立租户凭据、首次调用配置摘要、请求前后复核、响应上限和关闭、异常分类。核对安装的 SDK 使用无外部检索器的 Schema 注册表，没有将允许的旧关键字误报成已证实的网络访问漏洞。 |

两名独立审计者分别检查访问控制和持久化契约；另一名只读评审者复核修复差异，未发现新的 Critical/Important 阻断项。该结论限已读路径、最小复现与测试覆盖，不是绝对无漏洞证明。

保留的实际边界：

- 通用 HTTP 适配器允许受信任配置中的域名，不固定解析 IP；部署者仍需信任配置和网络。MCP 使用更严格的字面 IP 限制。本轮没有发现普通用户可改写目标的证据。
- Skill Schema 固定 Draft 2020-12，旧 `$recursiveRef` 不实施约束；本轮未改变旧包加载规则，后续收紧前须制定迁移方案。
- 每帧 SSE 鉴权会增加查询及角色配置读取，尚未做吞吐压测；没有宣称零性能开销。
- 本地配置文件与 SQLite 不构成跨资源的原子撤权事务。本次修复保证在关键执行点重新读取当前授权，不承诺分布式线性一致性。
- 没有进行真实模型、企业网络、生产写入、分布式部署、完整浏览器渗透测试或依赖漏洞数据库扫描。
