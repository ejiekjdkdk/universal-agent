# V3.1 P2 增量实施设计

基线main@af952ae；首轮P0/P1及两项审计修复保留。依据docs/design/V3.1.md第5、7、10、14节及V31-022～035。用户已授权评估后无阻断即开发，并明确选择：新的加密完整结果在任务结束后默认保留24小时，可配置，旧模式清理语义不变。

## 范围与决策

Windows Python3.11、现有SQLite与锁定SDK，不新增依赖，不连接真实企业系统。MCP继续以唯一MCPGateway接入，保留已有字面IP/受控回环HTTP与公网HTTPS策略，拒绝DNS/重定向/代理。补测批准的本机stdio开发传输与2025版本行为：没有实际通过的协议不得加入批准列表，明确拒绝也作为矩阵事实记录。生产DNS/私网、PostgreSQL、Provider Router、Replay不属于P2。

所有新增持久结果和共享只读缓存默认关闭，通过受信任服务器配置显式启用。MCP原配置仍能运行；目录批准摘要与缓存/熔断使用可选受信任配置，不从模型或远端自述获得批准。数值限额由实现者选择并写入使用文档，不要求用户逐项决定。

## 加密结果与兼容

新增ResultStore保存已通过Envelope、本地Schema、对象范围及秘密检查的完整工具结果。使用已锁定cryptography的AES-GCM、每次随机nonce；身份/业务/任务/执行ID/发布版本/到期时间等元数据作为AAD，防止跨行替换。256位密钥由本地操作者通过环境变量配置，不写入数据库/归档/日志；缺少或错误密钥拒绝启用/读取，不自动重置。保留key_id，支持读取既有key和选择当前写入key；移除旧key不得误判为空数据。

同一个Store SQLite连接和事务中增量创建专属结果表，不替换任务/执行权威记录。有效期默认86400秒，配置上限7天；按引用逻辑删除/吊销并删除密文，按TTL清理；本地文件物理擦除不作保证。存储总量、单结果字节/JSON深度/节点/数组/文本均有限额。用户已允许的24小时保留只适用于显式启用后的新结果，不回填旧结果。

Gateway仍返回完整data，旧内部execute/API/Worker签名不改变。启用后，完成调用的存储缓存可用内部加密引用代替完整明文；再次命中时在当前Gateway权限下解密完整结果。保存结果与完成调用需同事务并检查原租约，过期或被删除的缓存不能触发已完成工具盲重放。Durable步骤输出及其依赖/聚合继续保持原完整语义，须核查所有持久副本：如果仍有旧明文副本，不能声称整个执行数据全程加密，必须明确范围或完成对应内部引用适配。

新增可选结果路由：GET tasks/{task_id}/results列出本任务受控引用；GET results/{ref}返回摘要/元数据；GET results/{ref}/pages?cursor=...读取完整JSON的有界UTF-8片段，响应包含encoding、digest、offset和next_cursor；DELETE results/{ref}由原所有者提前删除。分页游标认证绑定ref、固定digest、页位置及有效期。通过顺序拼接UTF-8片段可恢复原完整JSON，不把任意嵌套data强改为行表。摘要/分页都要求原所有者、实时任务对象权限、固定及当前能力/技能/触发来源未撤销；任务正常终态不等于用户授权撤销。原run_context过期不能用于读已完成任务，需走现有任务所有权校验。

路由仅在部署者启用时注册，默认OpenAPI快照不变。客户端显式调用新增结果API即使用新协议，不改变旧chat/get_task/execute返回形状，不静默截断旧data。结果页响应带no-store。原答案和证据的既有保留规则不扩大为全文结果；日志只记录ID、digest、尺寸和错误类别。

P1编译器继续每回合重新授权。有ResultStore时，工具消息可携带受控result_ref，摘要仍完整保留证据；模型按有界读取入口请求页面，不能把引用当授权。未启用P2时P1请求内context_ref全部保留。只改变模型输入投影，不能改变Gateway.data和PlanWorker依赖值。

## 只读缓存与并发合并

按可信能力策略逐项启用；必须有正的短TTL及操作者维护的freshness/revision，缺失时不缓存。键包含租户/组织/用户、业务、固定和当前能力版本/Schema、权限摘要、对象范围、技能约束、参数规范摘要、数据时效要求、发布快照、MCP映射摘要/环境；不同任一项不合并。每个命中者重新鉴权，独立begin/complete_call、执行ID、结果引用及审计。

进程内single-flight只合并同一授权范围的实际只读查询；不宣称跨Worker/分布式合并。共享任务持有多个等待者，单个等待者取消/超时不取消其他仍获授权的等待者；所有等待者退出时终止并清理实际查询。授权回调必须基于仍存活且获授权的参与者，不能让首个调用者的取消使其它调用者绕过检查或继承身份。按实际物理尝试消费预算，命中仍消费逻辑调用预算，不允许靠共享绕过任一任务的上限。写操作、提案、agent嵌套调用和未知结果不进入此缓存。

缓存只保存有界已验证输出，错误不作为成功缓存；持久恢复仍依赖Store/PlanWorker原逻辑。故障重试由原Runtime控制，MCP SDK不得隐式重复工具执行。结果过期、权限撤销或策略变更均拒绝命中。

## MCP目录、健康与传输

缓存键绑定server_id、批准协议、目录digest、主体/权限范围、端点配置摘要及环境；即使服务器声称public，也不跨租户共享。读取ttlMs/cacheScope使用安装SDK的实际字段语义，施加平台上限；不理解则不缓存。缓存不能替代实时权限、映射摘要或撤销检查。

批准目录使用稳定的name/description/inputSchema/outputSchema摘要。可信本地检查命令生成候选目录及差异，由操作者写入批准配置；运行请求不能自动批准首次看到的内容。新工具不进入公开能力集。新增/删除/描述或类型变化标drifted并阻断，与目录缓存过期后刷新失败分开审计。调用时使用协议支持的Schema摘要保证缓存窗口内漂移不能执行不匹配工具；若SDK/协议无法保证，调用前强制刷新。

健康状态仅网关内部：healthy/degraded/open/half_open/disabled/incompatible；失败阈值、冷却、单个探测名额、并发/速率限制有界。disabled/incompatible保持拒绝，可信配置改变才重新评估，不因时间或探测自动批准。只读暂时错误允许原有有限重试；已发出的有副作用请求仍OUTCOME_UNKNOWN，不盲重试。取消不记为上游故障，所有探测/限流槽在异常或取消后释放。

stdio仅显式启用的本机开发模式、批准的绝对解释器/固定脚本参数/内容摘要和显式环境变量；不运行shell，不继承通用凭据，不允许用户/模型指定命令。校验Windows子进程树在超时和取消后回收。若不能满足边界，stdio保持拒绝并明确NOT_RUN，不能伪装支持；这不影响既有HTTP功能。
