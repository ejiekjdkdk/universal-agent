# V3 迭代基准

自 2026-11-03 起，V3 是当前开发目标与迭代基准。基准交付提交为 `2cfa57f`，已合并到私有仓库默认分支 main。V4、V5 作为长期架构愿景；未来大版本先评估价值、范围和兼容性，再由用户确认实施。

## 当前边界

以 [V3 本机框架验收](completion-acceptance.md) 中实现和验证过的能力为准：通用项目包、技能治理、即时和持久任务、MCP、触发器、Trace 与历史。继续支持 Windows、本机 Mock 和模型模式。业务通过独立项目包接入，不把行业规则放进核心代码。

PostgreSQL、企业生产联调、PKI/SSO 和自主多模型协作不是已完成能力。未来需要这些能力时，分别明确使用场景、部署边界与验收标准，不能把本机回归等同于生产验收。

## 代码约定

- 可读性优先于行数。用直观的变量、普通条件和循环表达步骤，复杂条件可以分成有意义的中间值或提前返回。
- 不为了形式抽取辅助函数、加装饰器、类、继承或通用包装。职责独立且有实际复用价值时才提取。
- 保留保证正确性的机制：事务和 savepoint、资源上下文、取消传播、锁与租约、执行前后授权、实际工具尝试预算。
- 说明性注释和 Docstring 使用中文，解释目的、边界和原因。协议名、错误码、公开错误文案和命令行帮助属于契约，不能当作注释随意翻译。
- 整理代码不随意改变接口、异常、业务逻辑、快照签名或数据格式。不增加非必要依赖。
- 发现真实缺陷时先复现，再以最小修改修复并补回归。涉及旧任务、已发布包或持久化数据的兼容性变化须单独说明。

## 建议阅读顺序

1. 从 `examples/v3/README.md` 跑通两个独立项目，认识业务、技能、证据和任务的关系。
2. 读 `app/main.py` 的 `create_app` 和聊天入口，了解鉴权、版本选择与任务入库。
3. 读 `app/runtime.py` 的 `Runtime` 和 `Gateway.execute`，跟随工具发现、权限、预算、执行、复核和重试。
4. 读 `app/catalog.py` 与 `app/mcp_gateway.py`，了解本地适配器和 MCP 如何遵守同一工具契约。
5. 读 `app/skills.py` 的导入、validate、stage、activate 和 load，区分草稿、评测、审核、发布及冻结内容。
6. 读 `app/triggers.py`、`app/store.py`、`app/plan_store.py` 和 `app/worker.py`，理解事件事务、计划领取、租约、取消和恢复。
7. 对照相应 `tests/test_*.py` 与 `docs/v3/` 文档确认边界，再修改所需模块。

本轮修改与兼容性结论见 [V3 可读性审计](../audits/readability-v3.md)。
