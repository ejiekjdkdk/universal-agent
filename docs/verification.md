## 本机离线耗时

每个场景通过回环 HTTP 顺序提交 20 次样例，均执行 1 次业务工具。P50 与 P95 按样本排序取最近秩。以下数值只描述本机这次运行。

| 场景 | HTTP P50 / P95 | 工具 P50 / P95 |
| --- | --- | --- |
| 资料问答 | 38.4 / 47.9 ms | 16 / 23 ms |
| 文本分析 | 32.4 / 38.4 ms | 11 / 13 ms |

要测试自己的模型，配置 README 所列环境变量后选择「模型模式」，询问示例资料中的事实。检查 Trace 中的模型轮次、工具执行、权限结果，并展开回答下方的证据核对原文。

## 独立项目接入验收

在 Windows 上将[接入模板](../templates/external-project/README.md)复制到仓库外，并在另一个目录签出接入前的底座提交 `19c6dff79d69590985081acdedc4df2498fb3881`。底座和项目后端以独立进程启动，使用真实的回环 HTTP 请求。底座仅从项目目录加载场景。以下是一次使用离线规划器的实测结果。

| 检查 | 实际结果 |
| --- | --- |
| 从项目自己的 `POST /ask` 发起请求 | 返回「DOC-101《会议模板》当前状态为已发布。」；证据来源为 `DOC-101`，版本为 `2` |
| 追溯调用 | 本次任务有 12 个 Trace 事件，`tool_result` 的执行 ID 对应 `lookup_record`，来源 ID 与证据一致 |
| 同键重试 | 两次提交返回相同任务 ID，项目服务的访问日志中该记录只有一次成功读取 |
| 项目权限与上游失败 | 用底座令牌请求记录接口得到 401。查询不存在的记录返回空证据。关闭项目服务后，新任务为 `failed`，错误为 `UPSTREAM_DEPENDENCY_FAILED` |
| 使用项目自己的数据 | 自动测试单独复制模板并修改项目记录状态，验证回答同步变化，证据与修改后的项目记录完全一致 |

包含本次接入测试的回归结果为 `102 passed, 12 subtests passed`。复现单项验收可运行 `python -m pytest tests/test_external_template.py -q`，也可以按模板说明直接对指定的旧版底座运行 `demo.py`。
