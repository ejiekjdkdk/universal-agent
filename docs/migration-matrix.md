# V2 到 V3 P1 的迁移对照

| 对象 | V2 基线 | 本轮处理与验收 |
| --- | --- | --- |
| 场景与工具 | 注册表从独立目录发现工具、权限和 Schema | 延用现有工具名。标准 Skill 名与业务 ID 分开校验，以发布清单绑定。第二项目接入只新增项目包及本机注册信息。 |
| Skill | V2 没有标准技能草稿与发布绑定 | 新增独立注册表、按业务发现、按需加载和运行时撤销。验证未发布、非法路径、缺失能力及版本固定。 |
| 场景快照 | 本地适配器和数据按文件清单冻结 | 多层技能引用由技能注册表冻结，不放宽原场景的文件边界。 |
| 规划与执行 | 已有离线、模型和持久计划 | Mock 经工具网关，技能约束随任务保存。两个纯虚构 Demo 通过公开 API 接入。 |
| 鉴权与数据 | 身份从可信令牌推导；对象、权限和历史随请求复核 | 技能所声明的工具只会收窄可执行范围。业务字段、技能文本和模型工具调用均不能授予权限。 |
| REST / SSE | blocking 即时返回、streaming 直接返回 SSE，持久计划 blocking 返回 202 | 旧行为继续由原测试覆盖。业务域技能与能力列表是新增接口，Trace 增加技能选择事件；断线按已存事件 ID 重放。 |
| 证据与审计 | 每次工具调用的标识、状态、耗时与来源可从任务/Trace 查看 | 网页展示所用技能和证据；验证授权记录查询及授权片段归纳都有实际调用记录。 |
| 治理与生产接入 | 已有本机模拟审批、发布、灰度、回滚和审计 | 保留并做回归。标准 MCP、外部服务、生产 PostgreSQL 与跨实例部署分别在后续阶段验收。 |
