# V2-P1 升级基线与边界

基线提交 `adc3c7c`，Windows、Python 3.11、FastAPI 和 SQLite。升级前运行 `python -m pytest -q`，102 项测试、12 项子测试通过。验收包括独立项目通过公开 HTTP API 调用底座。

| V1 的实际行为 | V2-P1 的升级契约 |
| --- | --- |
| `/chat` 以 `mode` 选择离线或兼容模型，阻塞返回 200，流式返回 SSE | 新增可选 `execution_mode`。旧请求仍走 reactive，旧幂等键的正文摘要兼容。持久任务显式选择 durable_plan |
| 会话、任务、工具执行、审计与事件存于 SQLite | 增量创建计划和步骤记录。旧数据库的任务、会话、历史事件和重放仍可读取 |
| Web 进程内驱动执行，重启后把未完成任务标记为失败 | 仅 reactive 沿用中断策略。durable_plan 由 Worker 按依赖和租约调度，已提交成功的步骤保留 |
| 已有工具输入输出 Schema、调用幂等、撤权检查、对象授权 | 计划只能调用已注册且获授权的只读能力。执行时再次校验当前权限和冻结版本，重试沿用逻辑调用 ID |
| 任务已有 Trace 和取消端点 | 增加计划与步骤视图。终态、步骤结果及相关事件须一致，断线后按事件 ID 重放 |
| 场景代码和数据属于各自项目 | 计划模板与业务适配器同属场景包。核心按能力和依赖调度，演示只使用本地数据 |

P1 只交付本地可恢复的只读执行。审批及模拟写入属于 P2，发布管理、灰度和评测门禁属于 P3。生产数据库、真实模型和企业授权体系的接入分别验收。
